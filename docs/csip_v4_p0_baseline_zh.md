## 0. 先看这里

1. **Pixiv 部分用错了数据源，B3-P1 / B3-P2 和 pixiv-artist-v1 不能用，也无法靠 "修正映射" 救回。**

## 3. 主指标 (三个模型，按画师 1,000 次 bootstrap，95% CI)

- 读出：默认分数 s·cos + b，各模型自带的 scale / bias。
  - v3 发布版：18.2881 / -9.875，默认阈值 -0.5819；
  - v3 x4：18.875 / -9.9375，阈值 0；
  - Kaloscope：38.226 / -18.096，阈值 0。
- 参照模型是 v3 发布版。diff 列为同一组重采样下的配对差 (其他模型 − 发布版)。
- `ap/<1y` 与 `pr_auc/<1y` 是同一个量：两者由同一个正负对直方图算出，表中只差在小数点后第 4 位。它不是独立的检索信号，读表时只算一项。
- 内容指标 `same_char_fpr` / `same_copy_fpr` / `cross_content_recall` 在各模型的默认阈值下计算 (裁定 R14)；JSON 里另有 `@best` 版本。
- **Task 16 新增的行** (§3.3 有解读)：
  - `pr_auc/<1y_xday`、`recall@1e-3/<1y_xday`、`recall@1e-4/<1y_xday`：<1 年层中去掉两张图原发日 (`date_day`) 相同的对 (裁定 R20 用校正后的原发日，不用上传日)，同一作品族的对照旧排除；
  - `recall@1e-4/<1y` 原来就在 JSON 里，现在也列进表；
  - `*@fpr1e-3` 在相同总体 FPR 下计算内容指标。阈值箱取 all 组负对尾部比例 ≤ 1e-3 的最低箱，同 `threshold_transfer` 的 `_fpr_bin`，每次 bootstrap 抽样各自定箱。`overall_fpr@fpr1e-3` 是该箱的实际总体 FPR。
  - `same_char_ratio@fpr1e-3` = `same_char_fpr@fpr1e-3` / `overall_fpr@fpr1e-3`，即同角色不同画师的误报率是总体误报率的几倍。
- **表的来源**：§3.1 / §3.2 由 `v3.scripts.bench2_tables` 从 `results_v2_{test,dev}.json` 生成。两表中原有的行与原 `results_{test,dev}.json` 的值完全相同。
- 年代指标只用原发日期可靠 (非上传时间) 的图作真值。
  - `date_mae_content` 排除共享角色 / 作品标签的近邻。这样候选不足 10 张的图更多，它和 `date_mae_baseline` 不是在同一批图上算的，不能直接相减。
  - `date_mae_upload_only` 是只有上传时间的图上的误差 (spec 要求单独报告)。
- **B1 上 Kaloscope 的分数：Kaloscope 训练中见过这些画师 (spec §5.2)**，B1 上它与 v3 的对比不公平 (对 Kaloscope 有利)。v4 vs Kaloscope 的公平对比目前只能看 B2 (B3-P2 不可用，§6.1)。
- B2 另报 "总体重加权" (`/reweighted`)：按画师的职业跨度和首图年份，重加权到 danbooru-artist-v2 中 ≥30 张图的 56,391 个画师。参考分布未被覆盖的质量：dev 0.12%，test 0.035%。

## 4. 阈值迁移 (G2 口径)

做法：每个来源各用 all 组曲线定 best-F1 阈值，迁移到其他来源，报告 F1 损失 (`pairwise.threshold_drift`，直方图估计)。

- spec 原定的 G2 集合还包括 B3-P2，因 §6.1 去掉；P0 检查点后 B3 整体取消。
  - 原 CLI 输出 (`results_{dev,test}.md` 和原 JSON 里的 `max_cross_f1_loss`) 含 B3-P2，是被污染的值，下表不用它。
  - 下表来自 `results_v2_{dev,test}.json`。其点估计与 `results_{dev,test}_g2fix.md` (由原 JSON 逐对损失重算) 完全相同。
  - `bench2.G2_SETS` = B1 + B2 + csip_eval_public，可用 `--g2-sets` 改。
- **CI 的做法 (Task 16)**：
  - 按画师配对 bootstrap，1,000 次，种子 0。B1、B2 各用 `evaluate_set` 里的同一个抽样矩阵 W，三个模型共用，所以模型差是配对差。

  - 然后重算各集合的 best-F1 阈值和逐对 F1 损失 (`curve_metrics` → `pairwise.threshold_drift`，与点估计同一条计算路径)，取 G2 集合之间的最大值。

### 6.1 Pixiv 部分用错了数据源 (阻断 B3 和 A7)

**现象**：B3-P1、B3-P2 上三个模型的 PR-AUC 都在随机水平。四个模型的 "同画师平均 cos − 跨画师平均 cos" 都接近 0：

**根因：s1 是 AI 生成图的语料库，不是 `pixiv_index` 所描述的那些人类作品。** 问题不只是连接时用错了 id，而是数据源本身选错了。下列检查一部分是我做的，一部分来自任务复核：

1. **来源**：s1 的数据集说明 (本地 HF 缓存里的 README) 标题为 "Pixiv AI-S1 4M Re-encoded Dataset"。
   - 它是另一个存储库 (`pixiv_ai_s1_storage`) 的重编码，"图片最大 id 8,848,846"。
   - s1 文件名的 id 是那个存储库自己的编号。
2. **尺寸 (AI 生成图的典型特征)**：
   - 复核抽 1,000 张 s1 图，没被缩到 4MP 的图 100% 宽高都能被 8 整除，89% 能被 64 整除，71% 正好是 SD 常用尺寸。
   - `pixiv_index` 作品的对应比例只有 18% / 2.2% / 0.2-0.3%。
   - 我另抽的 103 张未缩放 s1 图：被 8 整除 100%，被 64 整除 98%。
3. **尺寸与元数据对不上**：
   - 映射到的第 1 页图，宽高比与 `pixiv_index` 记录一致的只有 3.2% (500 行)，打乱配对后是 4.4%。
   - 原尺寸或按 4MP 缩放后的尺寸，500 行中 0 行一致。
4. **内容对不上**：我抽 80 个 "作品也在 Danbooru 上" 的 s1 第 1 页图，与该作品 id 对应的 Danbooru 帖子图比较 (16×16 灰度相关)。
   - 相关 > 0.9 的为 0/80；
   - 按最近邻能找回对应图的为 2/80 (随机水平 1/80)；
   - 目检的 4 对图内容完全不同，s1 一侧像 AI 生成图。
5. **`pixiv_index` 里没有 AI 作品**：`illust_ai_type` 只有 0 (未标注) 和 1 (非 AI)，从没有 2。
6. **为什么之前的检查没发现**：
   - `pixiv_index` 的图片 id 是 1 到约 1,505 万的连续整数，所以 s1 的 3,048,551 个 id 100% 都能连上；
   - `exist_ids.json` 也只是 s1 自身的 id 集合；
   - 元数据各表之间是自洽的，只有看图片内容和尺寸才能发现。

**结论**：任何 "修正后的映射" 都不可能从 s1 得到 spec 需要的人类画师 Pixiv 作品，s1 不能作为 Pixiv 部分的图片来源。

  - 实测约一半注入图来自另一个 split 的画师：B1 near_style 50.4%、same_char 48.7%；B2 near_style 49.3%、same_char 48.5%。
  - 只用于打分，不影响 split 隔离 (不调参、不训练)。

- **同日图对的处理 (与 spec §5.3 的差别)**：
  - 年代估计排除的是同一 **原发日期** (`date_day`) 的近邻，spec §5.3 写的是 "排除同一上传日"。
    - 日期校正到原发时间后，按原发日排除更合理：同一天发出的图通常是同一批，留着会让年代估计偏乐观；而上传日在校正后已不是年代真值。
  - 时间分层直方图 (PR-AUC / 召回) 和时间窗检索 (`map_at_r/1y`、`r1/1y`) 都没有排除同日图对，只排除了同一作品族。

  - Task 16 已加排除同日图对的时间分层层 `<1y_xday` (§3.3)：绝对值下降 0.004-0.019，模型间的配对差和显著性结论不变。

- **B1 总图数**：全部 split 合计 63,098 张，spec 粗估 "约 5 万"。这是因为补了 2025-2026 的新图、每画师上限 80，不是缺陷。B1 用 0918 `test_split.json` 的全部 800 个画师 (裁定 R7；spec 写 798，多出的几个也都在 v3 训练中被排除)。

  - R11：`cross_content` 正对包含没有任何标签的图对；
  - R12：聚类的 ARI / NMI 用 "噪声当各自单例" 的口径 (噪声整体当一类的版本在 JSON 的 `*_noise_as_class`)；
  - R14：内容 FPR 在默认阈值下计算。
